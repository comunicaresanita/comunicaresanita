# Architecture rules
- Desktop-only Home additions use responsive visibility in the shared article catalog and footer; shared scroll handling resolves page hash targets after rendering so FAQ links work from every page without changing mobile/tablet layout.
- External errors must pass through the shared Italian error mapper before display, and native form validation uses a shared Italian adapter, so provider and browser language cannot leak into app notices.
- Home-screen installability uses a manifest only and a role-independent shared banner with OS-specific instructions; an observed Home/dashboard slot retains the guide regardless of prompt preferences so existing accounts, asynchronous rendering and cross-browser fallback remain supported without an app-shell service worker.
- Contact submissions are validated and persisted by their dedicated Edge Function and exposed to the team through server-validated admin access, so no message relies on console logs or client-side success alone.
- Disabled service categories are removed from every catalog and blocked in the services table, so stale clients cannot restore retired offerings while historical bookings remain intact.
- Professional coverage is a required per-profile radius plus an optional drawn polygon that replaces the radius when present, evaluated by the shared isReachable rule in patient search and mirrored in the assistant, while the patient map always shows every professional so the list and the decorative map never depend on each other.
- Professional dashboard reads bookings through the get_professional_bookings security-definer function so the professional sees the patient's name/phone without opening patient profiles to them; professionals are redirected from the patient Home to their dashboard.
- Bookings are cancelled only through the cancel_booking security-definer function (patient or professional of the booking) and taken slots are read via get_booked_slots plus a partial unique index on active slots, so cancellation never depends on row-level update rules and cancelled slots become bookable again.
- Nurse, physiotherapy and OSS services, price bands (per visit or per hour) and info sheets come from generated per-profession catalogs (catalogoInfermiere / catalogoFisioterapista / catalogoOss + shared schedePrestazioni.json, lazy-loaded) mirrored by the nurse_service_catalog / physio_service_catalog / oss_service_catalog functions enforced in one services trigger, and every service name is rendered with the shared ServiceInfoButton and sorted alphabetically, so catalog, prices and sheets never drift apart.
